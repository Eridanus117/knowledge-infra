# ADR-005：检索编排迁移到 Python，采用分阶段替换

## 背景

受控运行环境可能使频繁生成和启动原生可执行文件成本过高或不稳定。对于仍在快速调整的同步、编排、过滤和诊断逻辑，这种摩擦会放大一次小改动的交付风险。

检索系统并不只有一种风险：语义候选、词法候选、融合、索引发布和诊断各自有不同的正确性边界。把实现语言替换误写成“重做事实源”或“一次性重写所有内容”，会破坏可逆性。因此本决定只改变可执行投影路径，不改变源材料的权威地位。

## 决定

### 1. 高频检索编排以 Python 实现

同步、投影发布、查询编排、过滤、诊断和评估适配层以 Python 实现。选择的理由是降低受控环境下的迭代摩擦，并使常见维护路径能以解释执行方式交付。

该决定不是“任何场景都禁止其他实现”的口号。若一个隔离的词法组件经公开、匿名评估证明 Python 候选无法满足既定质量门，可以保留一个冻结、独立版本化、接口固定的兼容组件。它必须是最后手段，不得重新成为高频变更的默认承载层。

### 2. 保持源—投影边界

Python 实现必须把源材料当作只读事实源，并发布新的可重建投影代际。它不得在索引过程中改写源文件、用缓存覆盖规范元数据，或把检索结果反写为事实。

新旧实现可在迁移期并行读取同一明确版本的源投影，但每个写入动作只能有一个权威写入方。切换后，旧投影只可作为受控回退或比较对象，不能继续与新投影混写。

### 3. 分阶段绞杀，而不是大爆炸替换

迁移按独立边界推进：

1. 先建立与现有输入、输出和诊断模式兼容的读取路径；
2. 再替换发布和同步路径；
3. 分别替换词法候选、融合与排序策略；
4. 每一步以功能开关隔离，并只在评估门通过后晋升默认值；
5. 每一步保留明确的回退点，回退只切换读写路径，不修改源材料。

任何阶段的输入缺失、来源身份不一致、投影版本不一致或后端响应无法解释时，系统必须大声失败并说明阶段和身份；不得静默回落到未知配置。

### 4. 评估门是语言迁移的晋升条件

每个候选实现必须使用显式提供的匿名案例集和固定匿名基线进行评估。公开评估器不得从未公开位置读取默认案例、默认基线或参考分数；不得用候选自己的输出生成基线。案例、基线和候选的来源集合、逻辑身份与规范版本必须一致，否则输出 `identity_mismatch` 或 `input_missing` 并以失败结束。

词法处理是迁移中需要单独证明的风险面。语义服务调用、融合策略、过滤逻辑和词法候选都必须分别暴露诊断，避免“总分看起来可以”掩盖某一层的退化。

## 合成示例

以下示例完全合成。

- `source-gamma` 的一个匿名文档进入旧投影和 Python 候选投影。两个投影都记录同一逻辑身份和来源版本，比较工具只比较公开的稳定标识与排序判据，不复制正文。
- Python 候选在词法阶段无法读取已声明的分析配置。它输出 `analysis_config_missing` 并停止该候选评估，而不是改用未声明的默认规则。
- 调用方提供了匿名案例集和候选，却遗漏基线。评估器输出 `input_missing` 并拒绝晋升；它不会探测任何默认位置。
- 评估门未通过时，功能开关保持旧读路径；源材料和已发布投影均不被回滚操作改写。

## 后果

### 正面

- 高频维护路径不再依赖频繁产生新的原生执行工件。
- 源材料、投影代际和评估工件的职责更清楚。
- 分阶段替换将风险压缩到可单独比较和回退的边界。
- 强制诊断使运行失败与质量退化不会混为一谈。

### 代价与约束

- Python 实现必须明确管理依赖、版本和运行环境，不能把环境偶然状态当作契约。
- 并行期需要严格限制写入权，避免两个实现互相覆盖投影。
- 评估门保护质量，但不替代对失败诊断、来源身份和新鲜度的检查。

## 否决的替代方案

| 替代方案 | 否决理由 |
|---|---|
| 维持所有高频路径的原生构建流程 | 不能消除受控环境下的迭代摩擦。 |
| 一次性替换全部组件 | 没有独立回退点，无法定位语言迁移造成的行为变化。 |
| 为了统一实现而接受词法质量退化 | 检索质量是产品行为，不能作为迁移便利的交换条件。 |
| 让评估器自动发现未声明的基线 | 破坏可复现性，并可能依赖非公开输入。 |

## 不在范围内

本决定不改变源材料 schema、逻辑身份模型或中央集合的来源范围剪枝契约。Python 实现必须遵守这些既有边界，而不是重新定义它们。
