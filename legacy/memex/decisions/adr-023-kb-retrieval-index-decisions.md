# ADR-023：检索与索引的公开决策

## 目的与边界

本决定记录检索投影的通用治理规则。它不把检索结果当作事实源：源材料、规范元数据和逻辑身份保持权威；中央集合、词法结构、语义结构、命中预览和评估报告都是可重建投影。

系统必须能回答四个问题：什么材料有资格进入投影；为什么某条候选被纳入、降权或排除；如何按稳定维度收窄；何时允许改变默认检索行为。不能以一次看似合理的结果或未公开历史分数代替这些回答。

## 决定

### 1. 默认相关性采用条件混合

查询规划器根据可公开解释的查询特征选择词法优先、语义优先或加权融合，而不是对所有输入使用单一固定混合。候选深度、融合权重、分析规则和任何排序先验都必须版本化并可关闭，以便单独评估其影响。

条件混合不是绕过质量门的调参入口。任何改变默认规划、候选深度、融合权重、分析规则或排序先验的提议，先作为非默认候选，再经过评估门，最后才可晋升。

### 2. 检索 facet 保持最小且语义明确

默认过滤维度为：

- `domain`：规范化的领域段；
- `kind`：源声明的种类；
- `tag`：规范标签。

逻辑来源身份用于 provenance、权限和显式来源收窄，但不把物理位置包装成普通检索 facet。中央集合保存 `source_id`、`document_id`、领域段、种类和投影版本，使一次检索能够按显式维度收窄。

### 3. 文档种类是排序先验，不是默认资格闸门

符合可索引性契约和来源范围策略的文档都会进入默认候选池。种类只能在候选融合后作为可评估、可关闭的排序先验；只有调用方明确请求时，种类才会成为范围过滤。未知种类不能因未在内部白名单中而被默认排除。

### 4. 命中返回指针与最小预览

检索结果返回稳定逻辑指针、来源身份、必要的 facet 和经过边界控制的最小预览，而不是内联完整正文。读取完整材料是后续、受来源权限控制的动作。这样可以限制上下文占用，也避免把投影输出误作原始材料副本。

### 5. 可索引性与运行故障必须大声可见

规范元数据是进入投影的前置条件。缺失、无效、身份冲突、范围排除、发布失败、投影过期、显式过滤造成空结果和候选资格拒绝，都必须产生结构化诊断。诊断至少包含阶段、匿名逻辑身份、稳定代码、策略版本和补救方向；不能把不同原因折叠为“未命中”。

### 6. 中央集合的剪枝按来源身份收窄

中央集合允许联合检索，但单来源同步只能对匹配该 `source_id` 的条目做孤儿判断和删除。缺失来源范围、未知来源身份或跨来源删除计划均必须失败。全量对账是独立、显式的流程，不能由日常同步隐式触发。

### 7. 公开评估门是改变默认值的唯一晋升机制

公开评估器必须只使用调用方显式提供的匿名案例集、匿名基线和候选配置。它不得读取未公开默认位置、未提供的参考分数或历史结果。评估输入必须声明：

- 案例集身份与版本；
- 覆盖的匿名来源集合；
- 每个案例引用的逻辑文档身份；
- 基线身份、评分规则版本和来源集合；
- 候选投影与策略版本。

以下任一条件必须失败并发出大声诊断：案例集、基线或候选输入缺失；来源集合不一致；案例文档身份无法解析；基线与候选的规范或策略版本不可比较；候选试图用自身输出充当基线。评估器不能用默认输入、默认分数或部分匹配结果继续运行。

质量门必须同时检查覆盖是否足以支撑结论，以及候选相对固定基线的表现是否满足预先声明的标准。门通过后才可翻转默认功能开关；未通过时，候选保持非默认并保留可解释诊断。

## 合成示例

以下示例完全合成，不含真实查询、正文或评分。

- `source-alpha` 与 `source-beta` 发布到中央投影。一个请求以 `domain` 收窄，另一个以显式 `source_id` 收窄；两者都引用逻辑身份，不依赖物理位置。
- `source-gamma` 引入一个新 `kind`。它进入默认候选池；某个候选策略可在融合后给予该种类有限先验，但不能在候选生成前删除它。
- `source-delta` 的某条材料缺少规范身份。构建输出 `logical_identity_missing`，不把它静默计入“未命中”。
- 一个公开评估调用提供匿名案例集和候选配置，却省略匿名基线。评估器输出 `input_missing` 并失败；它不会读取任何环境默认值。
- 另一次调用提供的基线引用了不同的来源集合。评估器输出 `identity_mismatch`，因此结果不能用于改变默认检索行为。

## 后果

### 正面

- 默认检索行为的每次变化都有独立候选、可比输入和明确晋升条件。
- 源、投影、过滤、排序和评估各自承担清晰职责。
- 新种类和新来源不会因隐式白名单或物理布局被默认排除。
- 缺失材料、过期投影、显式过滤和排序退化可以被分开诊断。

### 代价与约束

- 评估案例、基线和策略版本需要维护为公开的匿名工件。
- facet 语义是长期接口，变更需要迁移和重新评估。
- 对返回正文的便利性必须让位于来源权限、上下文控制和事实源边界。

## 否决的替代方案

| 替代方案 | 否决理由 |
|---|---|
| 对所有查询使用固定、不可解释的融合 | 无法针对不同查询特征诊断，也难以独立评估参数影响。 |
| 把物理来源位置作为普通 facet | 物理迁移会改变检索语义，破坏稳定身份。 |
| 以种类白名单决定默认候选资格 | 会使新种类或异构来源在排序前被静默排除。 |
| 内联完整正文作为标准命中返回 | 混淆投影与事实源，并扩大上下文和泄露边界。 |
| 凭直觉或候选自身分数翻转默认值 | 形成自我验证，无法证明与稳定基线可比。 |

## 不在范围内

本决定不规定具体模型、存储产品、参数数值或评估内容。它规定这些实现必须共享的身份、诊断、投影、来源范围剪枝和评估治理契约。
