# ADR-006：文档种类是排序先验，不是默认硬过滤

## 背景

不同知识来源会使用不同、且会演进的文档种类词汇。如果默认检索在排序之前只接受一份固定种类白名单，任何未登记的新种类都会被整批排除。结果看上去像“该来源没有相关材料”，实则是资格闸门在候选形成前已静默致盲。

种类仍然有价值：它可以帮助表达使用意图、支持显式范围收窄，并在质量被证明的前提下影响排序。但这些用途不要求默认把未知种类当作不可检索。

## 决定

### 1. 默认候选资格不按种类排除

只要文档满足可索引性契约和当前来源范围策略，它就进入默认候选池，无论其 `kind` 是已知、未知或未来新增值。种类不是源材料是否存在、是否可索引或是否允许默认召回的替代判断。

显式调用方请求可以使用种类收窄范围；该请求必须在结果和诊断中被记录为显式条件。默认查询不得偷偷注入种类白名单。

### 2. 种类只可作为后融合排序先验

种类影响默认结果时，必须发生在候选生成和融合之后，并以版本化、可关闭、可评估的排序先验实现。先验必须满足：

- 不会将未偏好的种类从结果集中删除；
- 能解释某条目的先验来源与版本；
- 与其他排序信号分开记录；
- 只有通过匿名评估门后才可成为默认值；
- 可以被关闭，以比较其真实影响。

若调用方使用显式种类过滤，结果为空、种类未知或过滤条件与来源范围冲突时，系统必须给出大声诊断，而不是返回看似正常的无结果。

### 3. 种类仍属于源—投影契约

`kind` 来自源材料的规范元数据，投影只复制并版本化这一事实。检索器不得为了迁就内部白名单而重写源种类，也不得把投影中的推断种类当成源事实。种类定义变化会改变投影策略版本，并需要重新评估其排序影响。

### 4. 评估对匿名输入严格失败

种类先验、显式过滤语义或默认候选资格的任何变化都必须通过匿名案例集和固定匿名基线。公开评估器必须要求这些输入由调用方明确提供；输入缺失、案例中的 `source_id` 或 `document_id` 与基线不一致、种类策略版本不一致时，评估必须失败并报告错误码。它不得回退到未提供的案例、分数或环境默认值。

## 合成示例

以下示例完全合成。

- `source-gamma` 提供种类为 `reference` 的匿名条目，`source-delta` 提供种类为 `guide` 的匿名条目。两者在满足可索引性契约后都会进入默认候选池。
- 一个排序配置偏好 `guide`。它只能在融合完成后上调相关 `guide` 条目的相对位置，不能让 `reference` 条目消失。
- 调用方明确请求 `kind=reference`，但请求的来源范围没有该种类。系统返回空结果并包含 `explicit_kind_filter_empty` 诊断，说明它是显式收窄造成的结果。
- 比较“先验开启”和“先验关闭”时，匿名案例集的身份与基线声明不一致。评估器以 `identity_mismatch` 失败，不输出可用于晋升的结论。

## 后果

### 正面

- 新来源和新种类不会因遗漏白名单而默认失明。
- 种类的业务语义被保留，而不是被改写成若干内部允许值。
- 排序偏好可独立测量、解释和回退。
- 显式过滤与默认召回的差异对调用方可见。

### 代价与约束

- 默认候选池可能包含更多不同种类的材料，因此排序和评估门必须承担质量责任。
- 种类先验的参数不是常量真理；每次默认值变更都需要可比评估。
- 诊断不能泄露正文或物理位置，只能引用匿名逻辑身份和策略版本。

## 否决的替代方案

| 替代方案 | 否决理由 |
|---|---|
| 扩充固定白名单 | 只能延后下一次遗漏，无法消除类型词汇演进造成的盲区。 |
| 将所有源种类改写为少数允许值 | 丢失真实语义，并把检索实现缺陷转嫁给源材料。 |
| 用种类做默认硬过滤，再要求使用者记住登记规则 | 把工具故障转化为记忆负担，且仍会静默排除未来种类。 |
| 直接把先验设为默认，不经过评估 | 无法证明排序改善来自策略而非不相容输入。 |

## 不在范围内

本决定不规定具体的先验公式、权重或种类 taxonomy。它规定默认检索的资格边界，以及任何种类偏好必须通过评估门的治理方式。
