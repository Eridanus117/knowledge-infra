# Embedding 队列螺旋：诊断、止损与恢复

> **公开替代文档。** 本 runbook 不包含真实服务名、端点、端口、主机、隧道、服务管理标签、配置路径、运行实例、查询或对象正文。所有示例均是抽象流程；`source-delta:unit-01` 只是合成 fixture identity。

## 适用条件

本流程适用于有效并发度很低（尤其是单 worker）的 embedding 上游。当客户端超时后，上游仍继续计算已被客户端放弃的请求时，短超时与自动重试会形成正反馈：旧请求继续占用 worker，新请求排队并再次超时，积压越来越深。

这不是“多试几次”能解决的问题。首先减少进入队列的工作量，才有机会判断上游本身是否健康。

## 症状

- 多个生产者同时出现请求 deadline、网关超时或等待时间异常增长；
- 即使使用最小合成 payload，单个请求也长时间无响应；
- 客户端取消数量增长，但上游完成数量没有相应下降；
- 重试量、队列年龄和响应时间一起上升。

这些信号只能说明请求路径拥塞；它们本身不能证明问题发生在客户端、本地代理、传输层还是上游 worker。

## 立即止损

1. **停止自动重试和新增批处理。** 暂停计划任务、人工运行和重试循环；不要用并发探测继续填满队列。
2. **保留观测，避免猜测。** 记录匿名化的队列年龄、活跃请求数、客户端放弃数、上游完成数和配置的并发度；不要记录请求正文、连接地址或身份信息。
3. **等待已有工作自然排空。** 若上游没有可靠取消协议，主动取消客户端连接并不等于释放上游 worker。
4. **只发一个合成探针。** 队列安静后，使用 `source-delta:unit-01` 的最小合成 payload 发送一次请求，且禁止并行探针。

## 分类决策

| 队列安静后的单一合成探针 | 判断 | 下一步 |
|---|---|---|
| 恢复到正常响应 | 队列螺旋；上游基础计算能力仍可用 | 修正 timeout、并发和重试策略后受控恢复 |
| 仍然缓慢或失败 | 不只是积压 | 沿传输和上游健康路径升级排查，保持生产者暂停 |
| 仅在并发恢复后变慢 | 上游容量低于生产者速率 | 施加并发上限与背压，分批恢复 |

不要把“本地资源正常”当成远端或代理链路正常的证据，也不要因一次探针成功就立即全量重放。

## 根因模型

设一次请求的上游计算时间为 `T_service`，客户端 deadline 为 `T_client`。若：

```text
T_client < T_service
```

且上游在客户端断开后继续执行，那么客户端会把请求标为失败，而 worker 仍被占用。重试请求排在这个已放弃请求之后；它们又在 deadline 到期前未开始或未完成，于是继续制造已放弃工作。多个生产者会把该反馈环放大。

如果上游支持端到端取消，客户端取消必须能被观测为上游实际取消；否则它只能减少等待者，不能释放容量。

## 恢复步骤

1. 保持唯一受控生产者，直到队列年龄稳定下降。
2. 将客户端 deadline 设为经批准的上界：

   ```text
   client_deadline >= service_time_bound + queue_wait_bound + safety_margin
   ```

   上界来自公开的容量假设或运行观测，不从私有配置隐式继承。
3. 若没有可靠取消协议，将 producer concurrency 限制在已知上游有效并发度以内，并让重试等待背压信号；不要立即重发超时请求。
4. 以幂等单位恢复同步。每个单位至少有稳定的匿名 identity 和内容摘要；已经成功写入且摘要未变的单位必须跳过，避免把恢复本身变成重复负载。
5. 先处理一个小的合成 fixture 批次，再逐步提高受控生产速率。每一步都观察队列年龄、完成率和 abandonment 是否保持稳定。

## 防复发控制

- **明示容量契约**：记录上游有效 worker 数、排队语义、取消语义和允许的生产者并发度。
- **可观测背压**：至少采集 `active_requests`、`queue_age`、`completed_requests`、`client_abandoned_requests`、`server_cancelled_requests` 与请求耗时分布。
- **重试纪律**：只对可重试错误使用有上限、带抖动、受队列状态约束的重试；超时不是立即并发重放的许可。
- **单写入者约束**：批量同步以显式租约或互斥保证同一目标在同一时段只有一个生产者。
- **恢复演练**：使用合成 payload 验证“暂停—排空—单探针—受控恢复”流程，不把真实查询、对象正文或运行连接带入公开材料。

## 升级条件

在队列安静、单一合成探针仍失败时，升级给负责上游或传输路径的人员。交接只应包含时间窗口、匿名指标、已暂停的生产者数、是否观察到实际 server-side cancellation，以及合成探针结果；不得包含真实 endpoint、主机、服务标签、请求文本或身份资料。

公开演练若缺少合成 fixture、身份注册表或配置的取消/并发语义，必须 fail loud，不得回退到私有默认路径、私有运行记录或历史得分。
